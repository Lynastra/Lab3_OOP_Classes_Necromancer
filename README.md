# Лабораторная работа №3: Основы ООП (Классы, Наследование, Полиморфизм)

**Предметная область:** Небольшой кусочек игровой вселенной (вдохновлено горячо любимой Diablo 2).
*Почему выбрана эта тема?* Классические примеры (геометрия или животные) слишком просты. И геометрия рассматривалась в двух прошлях заданиях Игровые сущности (персонаж и его прислужники) позволили наглядно продемонстрировать все требования методички (наследование, абстракцию, полиморфизм и работу с памятью) на понятной и логичной архитектуре.
И надо отметить, что это было приятнее и интереснее. Хотя с животными тоже могло выйти интересно, т.к. можно было брать мифических существ.

## Реализованная архитектура

В проекте реализована следующая иерархия:
1. **`Character` (Базовый класс)** — представляет обычного персонажа.
2. **`Necromancer` (Наследник `Character`)** — представляет некроманта, который может призывать нежить.
3. **`Minion` (Абстрактный класс)** — базовый класс для всех прислужников.
4. **`Skeleton`, `Spirit`, `BloodGolem` (Наследники `Minion`)** — конкретные виды нежити с уникальным поведением.

## Как выполнены требования методички (Задания 2.2 и 3.2)

### 1. Конструкторы
- В базовых классах (`Character`, `Minion`) реализованы конструкторы с аргументами.
- В классе `Necromancer` реализован **конструктор по умолчанию**, который вызывает другой свой конструктор через `: this(...)`.
- Конструкторы наследников (`Necromancer`, `Skeleton` и др.) вызывают конструкторы родительских классов через `: base(...)`.

### 2. Статические поля
- В классе `Character` есть статическое поле `TotalCharacters` (счетчик всех созданных персонажей).
- В классе `Minion` есть статическое поле `TotalMinions` (счетчик всех поднятых прислужников).
- В `Main` продемонстрирован вывод этих счетчиков.

### 3. Поле-экземпляр параметризованного класса
- В классе `Necromancer` реализовано поле `private readonly List<Minion> _minions`. Это параметризованный класс (generic), хранящий армию нежити.

### 4. Свойства разных видов
- **Только для чтения (`{ get; }`):** `Name` в классе `Character` (задается при рождении и не меняется). А также вычисляемое свойство `MinionCount` в классе `Necromancer`.
- **Только для записи (`{ set; }`):** `BindDemon` в классе `Necromancer`. Истинное имя демона вписывается в гримуар, но прочитать его обратно нельзя (чтобы демон не вырвался).
- **Для чтения и записи (`{ get; set; }`):** `Health` в классах `Character` и `Minion`. В сеттере реализована **валидация** (здоровье не может уйти в минус).

### 5. Скрытие членов базового класса (`new`)
- В классе `Character` поле `Title` и метод `Attack` **не являются виртуальными**.
- В классе `Necromancer` они скрыты с помощью ключевого слова `new` (свое поле `Title` и свой метод `Attack`).
- В `Main` продемонстрировано, что при вызове через ссылку `Character` срабатывает базовый метод, а через ссылку `Necromancer` — скрытый.

### 6. Совместимость типов (Upcasting / Downcasting)
- **Восходящее преобразование:** `Character baseRef = necro;` (безопасно).
- **Нисходящее преобразование:** проверка `if (baseRef is Necromancer castedNecro)`.
- Продемонстрирована работа оператора `as` (безопасное приведение с возможностью получить `null`).

### 7. Полиморфизм (Виртуальные методы и абстракция)
- Класс `Minion` — **абстрактный** (`abstract`). Нельзя создать объект «просто миньон».
- Метод `Attack()` в `Minion` помечен как `virtual`, а в наследниках (`Skeleton`, `Spirit`, `BloodGolem`) переопределен через `override`.
- В цикле `foreach (Minion minion in _minions)` вызывается `minion.Attack()`. Благодаря полиморфизму, каждый миньон атакует по-своему (скелет бьет мечом, голем — кулаком и лечится).

### 8. Деструкторы и работа с памятью
- Во всех классах реализованы деструкторы (финализаторы).
- Поскольку сборщик мусора (Garbage Collector) в C# работает непредсказуемо, для **гарантированной демонстрации** работы деструкторов в консоли используется метод `RunDemo()`, помеченный атрибутом `[MethodImpl(MethodImplOptions.NoInlining)]`. 
- После выхода из `RunDemo()` все локальные ссылки уничтожаются, и вызов `GC.Collect()` в `Main` гарантированно очищает память, выводя сообщения от деструкторов.
